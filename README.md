# Нічліг

Планувальник автоподорожі: вказуєте, звідки й куди їдете, а застосунок прокладає швидкий маршрут трасами, ділить дорогу на дні й підбирає готель на кожну ніч.

Демо: https://nichlih.pages.dev

Тестове завдання (AI Developer, Full-Stack). Опис для перевірки: [SUBMISSION.md](SUBMISSION.md).

## Запуск

Потрібен Node.js 20 або новіший.

```bash
npm install
npm run dev        # режим розробки, адреса з'явиться в терміналі
npm run build      # перевірка типів і збірка в dist/
npm run preview    # перегляд зібраної версії
npm test           # юніт-тести
```

Ключі й змінні середовища не потрібні: усі зовнішні сервіси, які використовує застосунок, відкриті.

## MCP-сервер для AI-агентів

Той самий планувальник доступний агентам (Claude, ChatGPT та іншим клієнтам MCP) як набір інструментів.

```bash
npm run mcp:build   # збірка в dist-mcp/
npm run mcp         # stdio, для локальних клієнтів
npm run mcp:http    # HTTP на http://127.0.0.1:8787/mcp (PORT, HOST змінюють адресу)
```

Підключити до Claude Code:

```bash
claude mcp add nichlih -- node /повний/шлях/до/проєкту/dist-mcp/main.js
```

Після цього достатньо попросити: «Сплануй поїздку машиною з Києва до Кракова, не більше 6 годин за кермом на день».

| Інструмент | Що робить |
|---|---|
| `plan_trip` | маршрут, поділ на дні, готель на кожну ніч, підсумок витрат |
| `night_options` | усі готелі для однієї ночі з сортуванням за оцінкою, ціною або гаком |
| `hotel_details` | контакти, координати, розбір ціни |
| `find_place` | пошук міста за назвою, якщо назва неоднозначна |

Усі інструменти лише читають дані. Маршрут кешується на добу, тож перепитування тієї самої поїздки миттєве. Окуповані території не обслуговуються: туди й крізь них маршрутів нема, готелів там нема.

## Що вміє

- Маршрут авто між двома точками, найшвидший, з часткою шляху великими дорогами.
- Поділ дороги на дні за часом за кермом (ліміт задає користувач).
- Готелі біля кінця кожного дня: ціна, відстань від траси, гак у хвилинах, сортування.
- Сторінка готелю зі знімками місця з повітря і розбором ціни.
- Збереження поїздок, демонстраційне бронювання, підписка (імітація без оплати).
- Дві верстки, телефон і десктоп. На широкому екрані їх перемикає кнопка збоку.

## Захист даних

- **Акаунтів нема.** Ім'я, налаштування й поїздки зберігаються лише в браузері (localStorage) і нікуди не надсилаються. У профілі є кнопка «Стерти мої дані з пристрою».
- **Назовні йде мінімум:** текст пошуку місця (Photon), координати точок маршруту (OSRM, Overpass). Жодних ідентифікаторів користувача.
- **Ключів і секретів нема** ні в коді, ні в збірці: усі сервіси відкриті.
- **Заголовки безпеки** (`public/_headers`, працює на Cloudflare Pages і Netlify): суворий CSP (скрипти лише свої, мережа лише до потрібних сервісів), заборона вбудовування в чужі сторінки, вимкнені камера, мікрофон, геолокація.
- **MCP-сервер** лише читає дані, перевіряє аргументи схемами zod, обмежує тіло запиту 1 МБ і за замовчуванням слухає тільки 127.0.0.1.

## Як це працює

1. **Маршрут.** OSRM повертає геометрію і час по кожному відрізку. Частку великих доріг рахуємо за номерами трас (E, М, Н, A, S, DK).
2. **Контрольні точки.** Ідемо вздовж маршруту за часом. Остання година перед денним лімітом це вікно ночівлі.
3. **Готелі.** Шукаємо в радіусі 10 км від ділянок, де може випасти ночівля. Для України й Польщі готелі лежать у `public/data/hotels.json` (вивантаження з OpenStreetMap), для інших країн іде живий запит до Overpass.
4. **Безпека.** Окуповані й сірі зони (мапа DeepState) виключені: застосунок не будує туди маршрутів, відкидає маршрути крізь них і не пропонує там готелів.
5. **Вибір.** Готелі оцінюються за гаком, ціною, зірками. Наступний день починається від вибраного готелю. Якщо у вікні готелів нема, день стає коротшим, але ніколи не довшим за ліміт.

Уся ця логіка лежить у `src/lib` і не залежить від інтерфейсу.

## Структура

```
src/lib/          ядро: маршрут, контрольні точки, планувальник, ціни, джерела даних
src/lib/__tests__ юніт-тести
src/pages/        сторінки
src/components/   карта, картки, іконки
src/data/         приклад плану для головної (зібраний з реальних даних)
public/data/      готелі України й Польщі
scripts/          прогін сценарію в Chrome
```

## Тести

`npm test` запускає 87 юніт-тестів. Вони покривають те, де помилка найдорожча:

- розбиття на дні: жоден день не довший за ліміт, останній доходить до фінішу, поведінка без готелів;
- оцінка й сортування готелів, фільтр бюджету;
- модель цін і її розбір на складники;
- розбір відповідей OSRM та Overpass з відсіюванням непридатних і підозрілих даних;
- окуповані території: точка в зоні, точка в дірці полігона, маршрут крізь зону, справжні межі (Севастополь, Донецьк, Мелітополь окуповані; Запоріжжя, Херсон, Харків ні);
- MCP-сервер справжнім клієнтом MCP через транспорт у пам'яті: схеми інструментів, поділ на дні, ручний вибір готелю, кеш маршрутів, відмова для окупованих територій, помилки зовнішніх сервісів.

Зовнішні сервіси в тестах не викликаються. Окремий живий прогін: `LIVE=1 npm test`.

GitHub Actions (`.github/workflows/ci.yml`) на кожен пуш і PR перевіряє типи, проганяє тести і збирає застосунок та MCP-сервер.

Сценарій у справжньому браузері (потрібен Google Chrome і запущений `npm run preview -- --port 4199`):

```bash
node scripts/walkthrough.mjs http://localhost:4199/ docs/screens 1440 900
```

## Обмеження

- **Ціни демонстраційні.** Їх рахує модель (тип закладу, зірки, сезон, день тижня). Справжні ціни готелів доступні лише за партнерськими договорами.
- **Бронювання й підписка імітовані**, оплати нема.
- **Без входу:** поїздки не синхронізуються між пристроями. Для тестового це свідомий вибір: нема особистих даних, нема чого захищати на сервері.
- **Знімки з повітря показують місце, а не сам готель:** фото готелів у OpenStreetMap нема.
- **Публічні сервери** OSRM, Overpass і плиток карти мають ліміти й можуть відповідати повільно.
- Час у дорозі без заторів. Гак до готелю оцінюється за відстанню до траси.
